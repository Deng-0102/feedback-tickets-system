# 智能分析：接口契约与提示词说明

> 对应代码：`backend/app/services/analysis_prompts.py`、`analysis_service.py`、`api/routes/analysis.py`
> 接口文档同步位置：`docs/api-conventions.md` 第 7 节（改字段时两处一起改）

---

## 1. 配置项

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `ANALYSIS_PROVIDER` | `deepseek` | `deepseek` 调真实模型；`mock` 离线演示；`off` 关闭（接口返回 503） |
| `ANALYSIS_API_KEY` | 空 | 模型平台密钥；为空且 `provider=deepseek` 时返回 503 |
| `DEEPSEEK_API_KEY` | 空 | 兼容写法，`ANALYSIS_API_KEY` 为空时才读它 |
| `ANALYSIS_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容地址，末尾不带 `/` |
| `ANALYSIS_MODEL` | `deepseek-chat` | 模型名 |
| `ANALYSIS_TIMEOUT_SECONDS` | `30` | 单次请求超时 |
| `ANALYSIS_MAX_RETRIES` | `1` | 仅对超时/429/5xx 生效，上限 3 |
| `ANALYSIS_TEMPERATURE` | `0.2` | 分类任务用低温度 |
| `ANALYSIS_MAX_INPUT_CHARS` | `4000` | 描述截断长度，最小 500 |

切换平台示例（阿里云百炼）：

```dotenv
ANALYSIS_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
ANALYSIS_MODEL=qwen-plus
```

## 2. 接口

### 2.1 执行智能整理

```http
POST /api/v1/tickets/{ticket_id}/analysis?force=false&apply=true
Authorization: Bearer <token>
```

| 参数 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `force` | query | `false` | `true` 忽略历史结果重新调用模型 |
| `apply` | query | `true` | `false` 只生成建议，不写回工单 |

权限：登录且工单可见（USER 本人提交 / AGENT 被分配 / ADMIN 全部），否则 404/40400。

成功响应（`data` 结构）：

```json
{
  "code": 0,
  "message": "智能整理完成，已写入工单，可人工修改",
  "data": {
    "ticket_id": 12,
    "result_id": 5,
    "status": "SUCCESS",
    "title": "修改密码后无法登录",
    "category": "ACCOUNT_LOGIN",
    "category_label": "账号登录",
    "summary": "用户修改密码后无法登录，重装后仍未解决，影响正常使用。",
    "keywords": ["密码修改", "无法登录"],
    "confidence": 0.92,
    "reason": "故障发生在修改密码之后",
    "model_name": "deepseek-chat",
    "prompt_version": "v1.0",

    "fallback_used": false,
    "applied": true,
    "cached": false,
    "error": null,
    "elapsed_ms": 2380
  }
}
```

失败响应（仍然是 HTTP 200）：

```json
{
  "code": 0,
  "message": "智能整理失败，已保留原始反馈，请人工填写分类",
  "data": {
    "ticket_id": 12,
    "result_id": null,
    "status": "FAILED",
    "title": "修改密码后一直无法登录",
    "category": null,

    "summary": null,

    "cached": false,
    "error": "TIMEOUT: 模型服务响应超时",
```

### 2.2 读取最近结果

```http
GET /api/v1/tickets/{ticket_id}/analysis
```

- 有结果：返回与 2.1 相同结构，`cached=false`、`applied=false`（历史记录不重复标记）；
- 没有结果：`404 / 40400`，`message="该工单还没有智能分析结果"`。

### 2.3 提交页预览

```http
POST /api/v1/analysis/preview
Authorization: Bearer <token>

{"description": "修改密码后一直无法登录，重新安装也没有解决。", "feature_module": "账号中心"}
```

- 不创建工单、不写数据库；
- `ticket_id`、`result_id` 为 `null`，`applied=false`；
- 适合 5 号在提交表单里做“智能整理”按钮。

## 3. 状态与错误码

| `status` | 含义 | 前端建议文案 |
|---|---|---|
| `SUCCESS` | 分类可信、字段完整 | “已自动整理，可修改” |
| `DEGRADED` | 结果可用但置信度 < 0.6，或分类被归一化/字段被截断 | “已整理，请确认分类” |
| `FAILED` | 模型失败或输出不可用 | “已保存，请选择分类” |

| HTTP | code | 场景 |
|---|---|---|
| 404 | 40400 | 工单不可见 / 尚无分析结果 |
| 422 | 42200 | 预览请求参数不合法 |
| 503 | 50300 | 未配置密钥、`provider=off` |
| 200 | 0 | 业务结果见 `data.status` |

`data.error` 的前缀即错误类型：`TIMEOUT`、`NETWORK`、`RATE_LIMIT`、`SERVER`、`AUTH`、`HTTP`、`BAD_RESPONSE`、`EMPTY`、`BAD_FORMAT`、`UNEXPECTED`。

## 4. 提示词全文（v1.0）

系统提示词（`SYSTEM_PROMPT`）：

```text
你是企业客服工单系统的“反馈整理助手”，负责把用户提交的一段口语化反馈，整理成工单标题、问题分类、摘要和关键词。

【分类范围】分类只能从下面五类中选择，禁止新增分类：
- ACCOUNT_LOGIN（账号登录）：登录、注册、密码、验证码、账号被锁定、权限被拒绝等身份相关问题。例如：修改密码后无法登录、收不到验证码、账号提示不存在
- FUNCTION_ERROR（功能异常）：某个功能报错、按钮无响应、数据不保存、页面白屏等功能缺陷。例如：导出按钮点击没有反应、保存后数据丢失、列表一直加载失败
- PERFORMANCE（性能问题）：卡顿、加载慢、超时、占用内存高等效率问题，功能本身可用。例如：打开报表要等两分钟、上传大文件时页面卡死
- USAGE_CONSULTATION（使用咨询）：询问怎么操作、功能在哪里、规则是什么，不涉及缺陷。例如：在哪里修改手机号、工单能导出成 Excel 吗
- FEATURE_SUGGESTION（功能建议）：希望新增或改进功能，属于需求而非故障。例如：希望支持批量导入、建议增加消息提醒

【输出要求】只输出一个 JSON 对象，不要输出 Markdown 代码块、解释文字或多余字段。字段固定为：
{
  "title": "简短标题，12 到 22 个汉字，概括用户遇到的具体问题，不要写“用户反馈”“问题”这类空话",
  "category": "上面五个英文分类代码之一",
  "summary": "摘要，40 到 100 个汉字，包含现象、发生条件、影响，只复述用户已提供的信息",
  "keywords": ["2 到 5 个关键词，每个不超过 10 个汉字"],
  "confidence": 0.0 到 1.0 之间的数字，表示你对分类判断的把握,
  "reason": "一句话说明分类依据，不超过 40 个汉字"
}

【硬性规则】
1. 只能依据用户描述和功能模块推断，禁止编造错误码、版本号、时间、金额等用户未提供的信息。
2. 描述信息不足时，选择最接近的分类并降低 confidence，不要凭空猜测。
3. 用户描述同时涉及多个问题时，以最主要的诉求分类，摘要中指出其余问题。
4. 摘要使用第三人称陈述，不写“您好”“我们会尽快处理”等客服话术，也不给处理方案。
5. 如果用户明确是在提需求而不是报故障，必须归为 FEATURE_SUGGESTION 或 USAGE_CONSULTATION，不能归为 FUNCTION_ERROR。
6. 输出必须是合法 JSON：字符串用双引号，关键词用数组，不要出现注释、尾逗号。

【示例】
用户描述：昨天改完密码以后就登不进去了，一直提示密码错误，卸载重装也没用，着急用。
功能模块：账号中心
正确输出：
{"title": "修改密码后无法登录", "category": "ACCOUNT_LOGIN", "summary": "用户修改密码后无法登录，系统持续提示密码错误，卸载重装后仍未解决，影响正常使用。", "keywords": ["密码修改", "无法登录", "密码错误"], "confidence": 0.93, "reason": "故障发生在修改密码后，且现象是登录失败"}
```

用户消息模板：

```text
功能模块：{feature_module}
用户描述：{description}
（描述是否被截断：是/否）
请按系统提示中的 JSON 契约输出结果。
```

## 5. 校验规则（代码即真相）

| 规则 | 常量 | 失败处理 |
|---|---|---|
| 标题最长 | `MAX_TITLE_CHARS = 40` | 截断，记 `issues`，降级 |
| 摘要最长 | `MAX_SUMMARY_CHARS = 200` | 截断，降级 |
| 关键词数量/长度 | `MAX_KEYWORDS = 6`、`MAX_KEYWORD_CHARS = 20` | 截断 |
| 置信度阈值 | `CONFIDENCE_THRESHOLD = 0.6` | 低于则 `DEGRADED` |
| 分类映射 | `CATEGORY_ALIASES` | 大小写、中英文、近义词统一到枚举 |
| 分类无法映射 | — | `FAILED`，转人工 |

分类别名表包含：英文枚举本身、中文分类名，以及 `登录/账号问题/BUG/故障/卡顿/咨询/建议/需求` 等常见说法。**新增分类或改分类名时，必须同步改 `CATEGORY_ALIASES` 和 `CATEGORY_LABELS`。**

## 6. 成本与性能

| 项目 | 估算 |
|---|---|
| 单次输入 | 约 700~1100 tokens（提示词约 600 + 描述） |
| 单次输出 | 100~250 tokens |
| 单次耗时 | 1.5~4 秒（`deepseek-chat`，视网络） |
| 25 条测试集 | 约 2.5 万 tokens，成本不到 0.2 元 |
| 课程演示 | 充 10 元足够，建议演示前预热一次 |

降本手段：默认复用历史结果、描述截断、`max_tokens=800`、失败不无限重试。

## 7. 手工调用示例（PowerShell，UTF-8）

```powershell
$body = [System.Text.Encoding]::UTF8.GetBytes('{"description":"导出按钮点了没反应，数据也保存不了","feature_module":"报表中心"}')
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/api/v1/analysis/preview' `
  -Headers @{ Authorization = "Bearer $token" } `
  -ContentType 'application/json; charset=utf-8' -Body $body
```

> 注意：PowerShell 控制台默认按 GBK 显示，中文可能显示为乱码，但请求内容本身是 UTF-8。**验收和截图建议直接用 Swagger 或 Apifox**，避免被控制台编码误导。
