## 3. 失败场景怎么造（联调/答辩演示用）

| 场景 | 操作 | 预期现象 |
|---|---|---|
| 未配置密钥 | `.env` 里 `ANALYSIS_PROVIDER=deepseek`、`ANALYSIS_API_KEY=` 留空，重启 | 503 / 50300，“未配置模型密钥” |
| Key 错误 | 把 Key 改成 `sk-wrong` | 200 + `FAILED`，`AUTH:` 前缀 |
| 超时 | `ANALYSIS_TIMEOUT_SECONDS=0.001` | 200 + `FAILED`，`TIMEOUT:` 前缀，工单标题不变 |
| 模型返回乱码 | 提示词里加一句“用 Markdown 回答”，或把 `response_format` 去掉并让模型自由发挥 | 200 + `FAILED`，`BAD_FORMAT:` 前缀 |
| 关闭功能 | `ANALYSIS_PROVIDER=off` | 503 / 50300 |
| 越权 | user002 拿 user001 的 ticket_id 调分析 | 404 / 40400 |

每个场景都要截“请求 + 响应 + 工单详情（确认未被改坏）”三张图。

## 6. 评审要点（老师可能看的地方）

- 测试是否覆盖**失败路径**，而不只是成功路径（本模块 9 个用例中 5 个是异常场景）；
- 失败时**数据是否完好**（工单标题、分类未被污染）；
- 是否有**权限测试**（越权返回 404 而不是 403，避免泄露工单是否存在）；
- 测试是否**可重复**（不依赖网络、不依赖真实 Key、不依赖执行顺序）。
